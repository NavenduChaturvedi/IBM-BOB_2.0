# Blast Radius + Rollback Runbook Generator — PRD & Architecture

Sep 26, 2026 · @Navendu Chaturvedi

## Overview

Most rollback plans get written under pressure, from memory, five minutes into an incident. This tool writes them before the deploy, from the actual diff. It's a CLI: feed it a PR diff, and it traces every caller and importer the changed code actually touches (blast radius, not guesswork), builds a pre-flight checklist tailored to what specifically changed (migration? breaking signature? new env var?), and generates a rollback runbook with real commands drawn from the repo's own deploy artifacts (Dockerfile, k8s manifests, migration files) — not "git revert and pray."

Built for: a solo dev or small team shipping a single-repo Python service who wants deploy confidence without a platform team. Built for: IBM Bob 2.0 hackathon (Sept 25–27, 2026), release/deployment track.

## Goals & Non-Goals

**In scope (MVP, hackathon build):**

- Single Python repo (not a cross-service/microservice mesh)
- Diff parsed from local git (`git diff main...branch`) or a GitHub PR URL
- Blast radius via import graph + caller search — deterministic, explainable
- Rule-based pre-flight checklist tied to diff content
- Rollback runbook generated by Bob, grounded in real repo artifacts (not hallucinated)
- CLI output only (markdown/terminal) — no web UI

**Explicitly out of scope:**

- True cross-service call tracing over the network
- Multi-language support (Python only)
- Full symbolic call-graph analysis (using text/import heuristics instead)
- CI/CD integration or a GitHub Action (post-hackathon roadmap)
- Auto-executing rollback commands (generates the runbook, doesn't run it)

## User Story

A dev opens a PR that touches a shared `payments/utils.py` function and a `users` table migration. Before merging, they run:

```
python blastradius.py --diff main...feature/refund-fix
```

In under a minute they get:

1. **Blast radius**: 4 files import the changed module; 2 functions call the changed function directly; 1 two-hop caller in `api/checkout.py`
2. **Pre-flight checklist**: "Migration detected — verify backward compatibility with the app version still running during rollout" and "Function signature changed, 3 known callers — confirm all updated"
3. **Rollback runbook**: exact `git revert <sha>`, `alembic downgrade -1`, and `kubectl rollout undo deployment/api` commands, generated from what's actually in the repo

They paste the output straight into the PR description. No incident-time guessing later.

## System Architecture

```
PR diff (git/GitHub)
      |
      v
[ Diff Parser ] -> changed files, functions/classes, file types
      |
      v
[ Blast Radius Engine ]        [ Pre-flight Checklist Generator ]
(import graph + caller search)         (rule-based)
      |                                       |
      +-------------------+-------------------+
                          |
                          v
         [ Rollback Runbook Generator ]
         (repo artifact scan + Bob)
                          |
                          v
              Markdown report (CLI output)
```

Two-track design: blast radius and the checklist are **deterministic** (grep/AST-based, no LLM guessing on facts). The rollback runbook is the one place an LLM (Bob) is used, and only after being grounded in real artifacts found in the repo — so it can't invent a `kubectl` command for a repo with no Kubernetes config.

## Component Deep-Dive

**1. Diff Parser** — `git diff` or the GitHub API returns the changed files list. For each `.py` file, AST-diff old vs. new to extract added/changed/removed function and class names. Classifies file types touched (migration, Dockerfile, requirements.txt, config, test).

**2. Blast Radius Engine** — Builds a repo-wide import graph (via `grimp`, or a custom `ast`-based walk as fallback). For each changed symbol: direct importers of its module, direct callers found via text/AST search, and second-hop callers of those callers. Output is ranked by proximity and labeled as heuristic, not claimed to be a perfect call graph.

**3. Pre-flight Checklist Generator** — Rule-based detectors against the diff and parsed metadata: migration file touched, new or changed env var read, public function signature changed with existing callers, no test file touched for changed logic. Each rule maps to a specific, non-generic checklist line.

**4. Rollback Runbook Generator (Bob)** — Scans the repo for deploy artifacts (Dockerfile, k8s manifests, GH Actions workflows, alembic/Django migrations, known feature-flag call patterns). Passes the diff plus detected artifacts to Bob with a constrained prompt: generate rollback commands using only the artifacts listed. Output is real commands (`git revert <sha>`, `kubectl rollout undo deployment/x`, `alembic downgrade -1`, a flag-toggle snippet), not generic advice.

## Tech Stack

| Layer | Choice | Why |
| --- | --- | --- |
| Language | Python 3.11+ | NV's strongest language, fastest to ship in |
| Diff parsing | gitpython + ast | Native AST diffing, no external parser needed |
| Import graph | grimp (fallback: custom ast walk) | Purpose-built for Python import graphs |
| Caller search | ripgrep (via subprocess) | Fast, simple, honestly heuristic |
| LLM/agentic layer | IBM Bob | Hackathon requirement; used narrowly for runbook generation only |
| Output | Markdown to stdout/file | No UI build time spent; judges see clean output |
| Demo repo | Small sample Flask/FastAPI app, seeded with git history | Needed for the 3 example PRs below |

## Example PRs (Demo Scenarios)

Three curated PRs in a sample repo, run and verified before the live demo — no live debugging on stage.

**PR 1 — Simple bugfix (low blast radius)** Change: fix an off-by-one error in `utils/pagination.py`, single function, no other files touched. Expected output: blast radius of 1 file, no migration or env flags, checklist mostly clean, rollback is a plain `git revert <sha>`. Demonstrates the tool doesn't cry wolf on trivial changes.

**PR 2 — Database migration (checklist trigger)** Change: a new alembic migration adding a `refund_status` column to `payments`, plus a model field update. Expected output: checklist flags "migration detected — verify backward compatibility," rollback runbook includes an `alembic downgrade -1` command with the actual revision ID pulled from the migration file.

**PR 3 — Breaking API signature change (biggest blast radius)** Change: `calculate_discount(price, code)` becomes `calculate_discount(price, code, user_tier)` in `payments/pricing.py`, called from three places across `checkout.py`, `cart.py`, and a test file. Expected output: blast radius lists all 3 callers by file and line, checklist flags "signature changed, 3 known callers — confirm all updated," rollback includes `git revert <sha>` plus a note on which callers to re-check post-revert. This is the demo's centerpiece.

## Risks & Known Limitations (say these to judges before they ask)

- Caller search is heuristic, not a true call graph. Text/import-based, will miss dynamic dispatch, reflection, or dependency injection patterns. Framed honestly as good enough to be useful, not perfect.
- Single repo, single language. No cross-service tracing over the network in this build — the architecture generalizes, the demo doesn't.
- Bob's output is grounded but not verified. The runbook is generated from real detected artifacts, but a human should still review before running commands in production.
- The 6-hour budget for the blast radius engine is the biggest schedule risk. If the import-graph library fights back, the fallback is pure ripgrep-based caller search — uglier, still works.

## Success Criteria (Demo)

- Tool runs end-to-end on all 3 example PRs with zero live failures
- Blast radius output is specific (file and line, not "somewhere in the codebase")
- At least one checklist item and one rollback command per demo PR is diff-specific, not generic boilerplate
- Judges can see the deterministic-vs-agentic split clearly — this is the pitch differentiator vs. a generic risk-score tool
- 3-minute demo fits: problem (30s), PR 3 walkthrough (90s), architecture callout on deterministic vs. Bob (60s)
