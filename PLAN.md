## 0. Decisions that deviate from / sharpen the PRD

| # | Decision | Why |
|---|----------|-----|
| D1 | **Custom `ast` import graph as primary, not `grimp`.** | grimp needs the target package importable on `sys.path` and has had friction on new Python versions (we're on 3.14). A ~120-line `ast` walker over the demo repo is fully in our control and removes the hour-4–10 schedule risk up front. |
| D2 | **AST call-site search as primary, ripgrep as a cheap pre-filter.** | `rg -l <symbol>` narrows candidate files; `ast` then finds real `Call` nodes with exact line numbers. Gives "file:line" precision (success criterion) without false hits from comments/strings. |
| D3 | **Runbook = deterministic template first, Bob second, validator last.** | Build a structured `RollbackFacts` object from the repo, render a template runbook with no LLM, then let Bob rewrite/order/explain it. A validator rejects any Bob command that references an artifact not in `RollbackFacts` and falls back to the template. The demo can never fail because Bob hiccups, and the pitch gets stronger: "grounded *and* checked". |
| D4 | **Local git diff only for MVP; GitHub PR URL is a stretch goal.** | Every demo scenario runs on local branches. PR URL support is ~1h via the GitHub REST API if time remains. |
| D5 | **Demo repo is generated by a seed script**, not hand-built. | `demo/seed_demo.py` creates `demo_repo/` with a fixed git history and the 3 PR branches. Rebuildable in seconds → zero-risk demo prep and golden-file tests. |

## 3. Core data model (`models.py`)

```python
ChangedFile(path, status: A|M|D|R, kind: python|migration|dockerfile|requirements|config|k8s|workflow|test|other,
            added_lines: list[str], removed_lines: list[str])
ChangedSymbol(file, module, qualname, kind: function|class|method,
              change: added|removed|body_changed|signature_changed,
              old_sig: str|None, new_sig: str|None, lineno)
Caller(file, line, enclosing_symbol, hop: 1|2, via_symbol, evidence: "call"|"import")
BlastRadius(importers: list[(file, line)], callers: list[Caller], score, label="heuristic")
ChecklistItem(rule_id, severity: high|med|low, text, evidence: list[str])
RollbackFacts(head_sha, base_sha, commits: list[sha],
              migrations: list[{tool: alembic|django, file, revision, down_revision}],
              k8s_deployments: list[{name, namespace, file}],
              docker_images: list[...], compose_services: list[...],
              workflows: list[...], feature_flags: list[{name, file, line}],
              new_env_vars: list[str], changed_callers: list[Caller])
```

## 4. Components — implementation notes

### 4.1 Diff parser (`gitio.py`, `diff_parser.py`) — 3h
- `git merge-base base head`, `git diff --name-status -M base...head`, `git diff -U0 base...head -- <file>` for added/removed lines.
- Old/new source via `git show <rev>:<path>`.
- AST diff: map `qualname → (signature_str, ast.dump(body) hash)` for old and new; classify added / removed / signature_changed / body_changed. Signature string built from `ast.arguments` (positional, defaults, kw-only, *args/**kwargs).
- File-kind classifier: path + content rules (`alembic/versions/*.py`, `*/migrations/0*.py`, `Dockerfile*`, `requirements*.txt`, `pyproject.toml`, `k8s/*.yaml` with `kind: Deployment`, `.github/workflows/*`, `test_*.py`).
- Handle syntax errors gracefully (fall back to "file changed, symbols unknown").

### 4.2 Blast radius (`import_graph.py`, `callers.py`, `blast_radius.py`) — 6h budget, target 4h
- **Import graph:** walk all `.py` files, path → dotted module name; record `import a.b`, `from a.b import c`, `from . import x` (resolve relative imports), with line numbers. Build reverse map `module → importers`.
- **Hop 1 callers:** for each changed symbol `pkg.mod.f`:
  - candidate files = importers of `pkg.mod` ∪ same file ∪ `rg -l -w f` hits (rg optional; fall back to scanning all files).
  - parse each candidate; resolve local alias (`from pkg.mod import f as g`, `import pkg.mod as m` → `m.f`), find `ast.Call` nodes matching → record line + enclosing function.
- **Hop 2:** treat each hop-1 enclosing function as a symbol, repeat once. Cap fan-out (e.g. 50) to avoid blowups.
- **Ranking:** direct callers > importers > hop-2; within tier sort by file path. Label output "heuristic: misses dynamic dispatch, getattr, DI".
- **Checkpoint at hour ~10 from start:** if hop-2 or relative imports are fighting back, ship hop-1 + importers only (PR 3 only needs hop-1 to hit its 3 callers).

### 4.3 Pre-flight checklist (`checklist.py`) — 3–4h
Rule registry: each rule is `fn(diff, blast, facts) -> list[ChecklistItem]`. Every item must quote evidence (file, symbol, revision id, env var name) so none are generic.

| Rule | Trigger | Example output |
|------|---------|----------------|
| `MIGRATION` | migration file added/modified | "Migration `a1b2c3` adds column `refund_status` to `payments` — verify the currently running app version tolerates it during rollout; confirm `downgrade()` is implemented." |
| `MIGRATION_NO_DOWNGRADE` | alembic `downgrade()` is `pass`/empty | high severity |
| `SIGNATURE_CHANGED` | signature_changed + callers | "`calculate_discount(price, code)` → `(price, code, user_tier)`, 3 known callers: checkout.py:42, cart.py:17, tests/test_pricing.py:9 — confirm all updated." Also flag callers **not** touched in this diff. |
| `SYMBOL_REMOVED` | removed symbol with callers | high |
| `NEW_ENV_VAR` | added lines match `os.environ[..]`, `os.getenv(..)`, `os.environ.get(..)` | "New env var `REFUND_API_KEY` — set it in every environment before deploy." Cross-check against k8s manifest `env:` / `.env.example`. |
| `NO_TESTS` | logic `.py` changed, no test file changed | med |
| `DEPS_CHANGED` | requirements/pyproject changed | "Rebuild image; pin versions." |
| `DEPLOY_CONFIG_CHANGED` | Dockerfile/k8s/workflow changed | med |

PR 1 must produce a *clean* checklist (no false alarms) — this is a test case.

### 4.4 Artifact scan + runbook (`artifacts.py`, `runbook/*`) — 5h
- **Scan:** Dockerfile(s), `docker-compose*.yml`, k8s YAML (`kind: Deployment` → name/namespace), `.github/workflows/*.yml`, `alembic.ini` + `alembic/versions/*.py` (parse `revision` / `down_revision` via ast), Django `migrations/`, feature-flag patterns (`is_enabled("x")`, `flags.get("x")`, `FEATURE_*` env vars).
- **Template runbook (no LLM), ordered:**
  1. Decide trigger conditions (from checklist high-severity items).
  2. If feature flag touched → toggle flag first (fastest rollback).
  3. `kubectl rollout undo deployment/<name> -n <ns>` (only if manifest exists) / `docker compose ...` equivalent.
  4. `alembic downgrade <down_revision>` (real id, not just `-1`) — ordered *after* app rollback so old code never meets missing schema... noting the data-loss risk if the column was populated.
  5. `git revert --no-edit <sha…>` for the PR's commits.
  6. Post-rollback verification: re-check listed callers, smoke endpoints.
- **Bob step:** prompt = diff summary + `RollbackFacts` JSON + template runbook + hard rules ("use only these deployment names / revisions / shas; do not invent commands"). Bob improves ordering rationale, risk notes, verification steps.
- **Validator:** extract fenced shell commands from Bob output; check every `kubectl … deployment/X`, `alembic downgrade R`, `git revert S`, `docker …` against `RollbackFacts`. Any unknown identifier or tool with no artifact → reject, fall back to template, and print "Bob output rejected: referenced deployment `web` not found in repo". (That rejection line is itself a great demo moment.)
- **Backends:** `BobBackend` (API, if available), `FileBackend` (ingest Bob output from IDE), `NoneBackend` (`--no-llm`, template only).

### 4.5 CLI + report (`cli.py`, `report.py`) — 3–4h
```
python blastradius.py --diff main...feature/refund-fix [--repo PATH] [--out report.md]
                      [--no-llm | --bob-output FILE] [--format md|json] [--hops 2]
```
Report sections: header (base/head, shas, files changed) → **Blast radius** table (symbol, change, file:line, hop) → **Pre-flight checklist** (`- [ ]` items with severity) → **Rollback runbook** (numbered, fenced commands, "generated by: template | Bob (validated)") → **Limitations** footer. Markdown is paste-ready for a PR description. Target runtime < 10s on demo repo.
